1. Assignment Objective 
The objective of this assignment is to understand how Machine Learning models are 
developed, deployed, monitored, and maintained in real-world production environments. 
Students are required to analyze a given business scenario and design an appropriate MLOps 
workflow/pipeline for solving the problem. 
The assignment is inspired by real-world MLOps use cases such as fraud detection, demand 
forecasting, predictive maintenance, recommendation systems, customer-support automation, 
anomaly detection, churn prediction, and computer-vision quality inspection. 
 
2. Case Study Scenarios 
Choose ONE of the following scenarios. 
Scenario 1: Online Payment Fraud Detection 
A digital payment company processes thousands of transactions every minute. The company 
wants to develop an ML model that identifies potentially fraudulent transactions in real time. 
The model should classify a transaction as: 
• Genuine 
• Suspicious 
• Fraudulent 
However, fraud patterns change frequently, and a model that performs well today may 
become less accurate over time. 
Your Task: 
Design an MLOps solution that explains: 

=== PAGE 2 ===
1. How transaction data will be collected. 
2. How data will be preprocessed. 
3. How the fraud detection model will be trained. 
4. How the model will be deployed for real-time prediction. 
5. How model performance will be monitored. 
6. How the model will be retrained when fraud patterns change. 
7. How model versions will be managed. 
8. How a failed model deployment can be rolled back. 
 
Scenario 2: Retail Demand Forecasting 
An e-commerce company wants to predict the demand for different products for the next 7 
days. 
The company has historical information about: 
• Product sales 
• Price 
• Discounts 
• Festivals 
• Seasons 
• Location 
• Customer demand 
The company wants to reduce both stock-outs and excess inventory. 
Your Task: 
Design an MLOps pipeline for the demand forecasting system. 
Your solution should explain: 
1. Data collection and storage. 
2. Data preprocessing and feature engineering. 
3. Model training. 
4. Model evaluation. 
5. Batch prediction. 
6. Model deployment. 
7. Automated retraining. 
8. Monitoring of prediction accuracy. 
9. Handling of data drift. 
10. Important business KPIs. 
 
Scenario 3: Predictive Maintenance in Manufacturing 
A manufacturing company has machines equipped with sensors that continuously record:

• Temperature 
• Vibration 
• Pressure 
• Operating hours 
• Machine speed 
The company wants to predict whether a machine is likely to fail within the next 24 hours. 
Unexpected machine failures result in significant production losses. 
Your Task: 
Design an end-to-end MLOps solution. 
Explain: 
1. How sensor data will be collected. 
2. How time-series data will be processed. 
3. What features can be extracted.

6. Whether you would use edge or cloud deployment and why. 
7. How model performance will be monitored.

9. How model updates will be deployed safely. 
10. What KPIs should be monitored.

3. Common Requirements for All Scenarios 
Your case study must include the following components: 
A. Problem Definition 
Clearly explain: 
• What is the business problem? 
• Why is ML required? 
• Who will use the prediction? 
• What is the expected outcome? 
B. Data Pipeline 

=== PAGE 6 ===
Explain: 
Data Source → Data Collection → Data Storage → Data Preprocessing → Feature 
Engineering 
C. ML Pipeline 
Explain: 
Training Data → Model Training → Model Evaluation → Model Selection → Model 
Registry 
D. Deployment 
Explain how the trained model will be deployed. 
You may consider: 
• REST API 
• Batch deployment 
• Real-time deployment 
• Edge deployment 
• Cloud deployment 
• Docker/containerization 
E. Monitoring 
Identify what should be monitored after deployment. 
For example: 
• Model accuracy 
• Precision 
• Recall 
• Latency 
• Data drift 
• Prediction drift 
• System performance 
• Business KPI 
F. Retraining 
Explain: 
• When should the model be retrained? 
• What new data will be used? 
• How will the new model be evaluated? 
• Who/what will approve the new model? 

=== PAGE 7 ===
G. Versioning and Rollback 
Explain how you would maintain: 
• Dataset versions 
• Code versions 
• Model versions 
• Pipeline versions 
Also explain what happens if the newly deployed model performs poorly.
